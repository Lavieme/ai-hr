# 知衡 · 校招筛选工作台

知衡帮助 HR 整理岗位材料、按统一标准复核候选人，并形成有原文依据的推荐名单。团队通过共享密码进入同一个工作台，项目、材料和复核记录持续保存。

**准备材料 → 复核候选人 → 交付名单**

## 功能

| 功能 | 可以完成的工作 |
| --- | --- |
| 项目管理 | 创建、编辑和删除招聘项目，一键创建示例项目体验完整流程 |
| 材料导入 | 粘贴 JD 和简历，上传 TXT、Markdown、DOCX、文本型 PDF，批量导入简历 |
| 材料整理 | 检测重复简历，查看异常提示，手动补充或修正解析后的文字 |
| 评价卡 | 编辑评价标准、证据要求和优先级，使用 AI 起草标准，保存模板并跨项目复用 |
| 版本与确认 | 查看评价卡历史版本，记录用人经理确认，修订后提醒重新检查已有复核 |
| 候选人复核 | 逐项核对原文证据、记录说明及待核实问题，人工保存结论和推荐依据 |
| 盲筛 | 在复核界面和名单导出中隐藏姓名、联系方式和院校信息 |
| 名单交付 | 查看人工确认进入面试的候选人，导出评价卡、名单 CSV 和交付摘要 |
| 反馈记录 | 记录经理意见和后续反馈，为调整材料及标准提供参考 |

## 使用流程

### 1. 准备岗位和候选材料

登录后新建项目，填写或导入 JD。文件提取的文字会先进入编辑框，核对后点击“保存岗位材料”。简历可以粘贴，也可以多文件上传。

系统会提示重复、内容不足和解析失败的材料。扫描 PDF 或损坏文件保留原件，可手动补充正文后继续复核。首次使用也可以从首页“一键体验示例”创建包含虚构材料的项目。

### 2. 确认评价卡

在“筛选依据”中编辑每项标准、期望证据和优先级，也可以基于 JD 生成 AI 草稿。草稿经过人工核对并保存后才生效；常用评价卡可以保存为模板。

评价卡每次保存都会生成新版本。已有人工结论会提示重新检查，用人经理的确认信息需要重新记录。修改 JD 后，可在此重新生成或手动调整评价卡。

### 3. 逐项复核候选人

选择候选人，按评价标准核对原文。AI 可以提取相关引用、缺失信息和待核实问题，HR 再逐项确认“有证据”“证据不足”或“待核实”，补充说明和追问。

复核后，由 HR 选择是否建议进入面试、需要补充信息或暂缓，并保存具体依据。修改简历正文后，旧 AI 结果和逐项证据会被清除，需要重新复核。

### 4. 交付名单并记录反馈

推荐名单只包含 HR 明确选择“建议进入面试”的候选人。保存这一结论时，需要至少确认一项原文证据，或填写至少 5 字的具体依据。评价卡修订后尚未重新检查的记录会明确标注。

按需要导出评价卡、名单 CSV 和交付摘要，并在“经理反馈”中记录意见。反馈不会自动改变评价卡或候选人的人工结论。

## AI 如何参与

AI 负责起草评价标准、查找简历原文证据，以及整理缺失信息和待核实问题。最终招聘结论由 HR 确认。

证据引用必须逐字存在于简历原文中，并关联生成时使用的评价卡版本。调用由用户主动触发，失败时保留已保存结果。未配置 AI 时，仍可使用规则草稿和完整的人工复核流程。

## 材料与盲筛

- 支持 TXT、Markdown、DOCX 和文本型 PDF；简历每批最多上传 30 份，单文件最多 15 MB，PDF 最多 12 页。
- 扫描 PDF 需要手动补充文字，暂不提供图片 OCR 或 ZIP、JSON 导入。
- 盲筛隐藏界面和名单导出中的身份信息；查看或编辑原始简历需要关闭盲筛。盲筛用于复核展示，不提供账号级权限隔离。
- 原件保存在私有 S3 兼容存储，下载使用临时签名链接。未配置存储时仍可粘贴文本。

## 开始使用

打开工作台，使用登录页展示的访问密码登录。密码由 `APP_PASSWORD` 配置，默认示例值为 `zhiheng-demo`；自定义密码也会显示在登录页。

开发启动、环境变量和验证命令见 [开发与配置](docs/development.md)，自动构建和部署设置见 [GitHub Actions](docs/ci.md)。
